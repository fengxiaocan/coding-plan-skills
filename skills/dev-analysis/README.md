# Dev Analysis — 功能分析文档生成

本 Skill 用于**分析已有代码功能，生成可长期维护的功能说明文档**。只理解、只解释、只沉淀，不评价、不建议、不修改。

---

## 触发命令

在 Claude Code 对话中输入：

```
/dev-analysis
```

或明确请求分析某个功能/模块，例如：

- "帮我分析一下游戏扫描功能"
- "整理一下 ROM 识别模块的文档"
- "我想理解 Moonlight 串流这块代码"

---

## 用途

| 场景 | 说明 |
|------|------|
| 学习代码 | 快速理解陌生模块的实现方式 |
| 补充文档 | 为缺少文档的功能生成标准化说明 |
| 项目交接 | 沉淀功能文档，便于后续维护 |
| 新成员培训 | 作为学习材料，帮助新人了解核心功能 |
| 功能梳理 | 系统性地回顾模块结构与数据流 |

---

## 核心原则

1. **只理解代码**：分析模块结构、调用关系、数据流、配置依赖
2. **只解释代码**：用结构化语言描述功能行为
3. **只沉淀文档**：按模板输出到 `docs/{模块名}/README.md`

**禁止输出以下内容：**

- Bug 分析
- 风险分析
- 技术债务
- 代码质量评价
- 重构建议
- 优化建议

---

## 工作流程

```
阶段 1: 需求确认 → 确认功能范围、代码位置、分析目标、输出位置
阶段 2: 代码阅读 → 分析模块结构、调用关系、数据流、配置依赖
阶段 3: 文档生成 → 按模板生成功能说明文档并保存
```

详细说明见 [USAGE.md](USAGE.md)。

---

## 文档模板

生成的功能说明文档使用统一模板，包含：功能概述、模块位置、整体架构、核心流程、调用链分析、数据流分析、关键类说明、关键函数说明、配置说明、对外接口、使用场景、时序说明、总结。

模板文件见 [TEMPLATE.md](TEMPLATE.md)。

---

## 输出位置

```
docs/{模块名}/README.md
```

- 例：`docs/game-scan/README.md`
- 如果 `README.md` 已存在，保存为 `README-v2.md` 或询问用户是否更新原文档

```
├── USAGE.md      # 使用文档：完整流程、示例、规则
└── TEMPLATE.md   # 文档模板：标准化输出结构
```

---

## 全局规则

| 规则 | 说明 |
|------|------|
| 每轮最多 3 个问题 | 逐步推进，不一次性 overwhelm 用户 |
| 禁止跳过阶段 | 必须按顺序完成 1→2→3 |
| 禁止提前分析 | 未确认需求前不得直接打开代码 |
| 禁止编造 | 不得虚构不存在的逻辑 |
| 禁止评价 | 不得输出 Bug/风险/债务/质量/重构/优化建议 |
| 标记不确定性 | 无法确认的信息标记为 `【待确认】` / `【代码中未发现】` |
| 文档必须保存 | 分析结果必须输出到 `docs/{模块名}/README.md` |
