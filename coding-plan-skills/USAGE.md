# Coding Plan Skills 使用文档

## 用途

`coding-plan-skills` 是三个开发工作流技能的集合库，覆盖 **修复问题 → 开发规划 → 变更归档** 的完整开发链路。

包含三个子命令：
- `/fix-plan` — 调试访谈（修复 Bug）
- `/dev-plan` — 开发规划（新需求）
- `/dev-change` — 变更记录（任务归档）

---

## 触发方式

在 Claude Code 对话中输入对应命令：

```
/fix-plan   # 开始修复问题的信息收集流程
/dev-plan   # 开始新需求的规划流程
/dev-change # 生成本次变更的 CHANGELOG
```

---

## 完整工作流

### 场景一：修复 Bug

```
用户: /fix-plan App 崩溃了
      ↓
AI:   [阶段 1~4] 收集问题信息、环境、复现步骤、证据
      ↓
AI:   [阶段 5] 输出问题摘要 → 等待用户确认
      ↓
用户: 确认
      ↓
AI:   [阶段 6] 根因分析 + 修复方案（不写代码）
      ↓
AI:   [阶段 7] 满足条件后开始修复代码
      ↓
用户: /dev-change 生成变更记录
      ↓
AI:   生成 docs/CHANGELOG-YYYY-MM-DD.md
```

### 场景二：新需求开发

```
用户: /dev-plan 加一个深色模式
      ↓
AI:   [阶段 1] 多轮需求采访
      ↓
AI:   [阶段 2] 生成任务说明书 → 等待用户确认
      ↓
用户: 确认
      ↓
AI:   [阶段 3] 生成实施计划 → 等待用户确认
      ↓
用户: 确认
      ↓
AI:   [阶段 4] 生成验收清单 → 等待用户确认
      ↓
用户: 确认
      ↓
AI:   [阶段 5] 开始编码
      ↓
AI:   [阶段 6] 输出交付报告
      ↓
用户: /dev-change 生成变更记录
      ↓
AI:   生成 docs/CHANGELOG-YYYY-MM-DD.md
```

---

## 各子命令详情

| 命令 | 完整文档 | 阶段数 | 核心约束 |
|------|---------|--------|---------|
| `/fix-plan` | [fix-plan.md](fix-plan.md) | 7 阶段 | 信息收集完成 + 用户确认后才编码 |
| `/dev-plan` | [dev-plan.md](dev-plan.md) | 6 阶段 | 需求确认 + 计划确认 + 验收确认后才编码 |
| `/dev-change` | [dev-change.md](dev-change.md) | 10 章节 | 基于实际代码修改生成，禁止编造 |

---

## 全局设计原则

```
┌─────────────────────────────────────┐
│  1. 禁止提前编码                      │
│     未完成信息收集/规划前不写代码      │
├─────────────────────────────────────┤
│  2. 逐步确认                         │
│     每阶段结束需用户确认才能继续       │
├─────────────────────────────────────┤
│  3. 诚实记录                         │
│     禁止编造验证结果                  │
├─────────────────────────────────────┤
│  4. 渐进式提问                       │
│     每轮最多 2~3 个问题              │
└─────────────────────────────────────┘
```

---

## 适用场景

- **团队开发**：统一 AI 辅助开发的工作流程
- **代码审计**：变更记录可追溯、可审计
- **新成员交接**：通过 CHANGELOG 快速了解历史变更
- **问题追踪**：结构化的调试访谈确保不遗漏关键信息

## 使用建议

1. **养成习惯**：任务完成后习惯性执行 `/dev-change`
2. **耐心配合**：`/fix-plan` 和 `/dev-plan` 的信息收集可能需要多轮
3. **主动提供**：设计文档、参考实现、错误日志等信息主动提供可加速流程
4. **严格确认**：阶段确认节点是避免返工的关键，请认真审阅后再确认
