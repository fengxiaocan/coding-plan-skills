# Dev Plan 使用文档

## 用途

`dev-plan` 用于**新需求开发、功能实现、添加功能**时，强制要求 AI 先完成需求采访和任务规划，再进入编码阶段。

**核心理念**：先规划后编码，明确目标、范围、验收标准，避免返工。

---

## 触发方式

在 Claude Code 对话中输入：

```
/dev-plan
```

或描述开发需求时 AI 自动触发（当检测到实现/添加/构建等关键词时）。

---

## 工作流程（6 阶段）

```
阶段 1: 需求采访    → 多轮对话收集项目背景、目标、范围、参考资料、交付要求
阶段 2: 任务说明书  → 生成结构化任务说明书，等待用户确认
阶段 3: 实施计划    → 生成技术方案和步骤，等待用户确认
阶段 4: 验收清单    → 生成功能验收和回归验证清单，等待用户确认
阶段 5: 开始实施    → 三项全部确认后才能写代码
阶段 6: 交付报告    → 完成后输出交付报告
```

---

## 需求采访要点（15 项）

### 项目背景
1. 项目是做什么的？
2. 当前架构是什么？
3. 本次涉及哪些模块？

### 目标
4. 用户真正想解决什么问题？
5. 为什么要做这件事？
6. 最终效果是什么？

### 范围
7. 本次明确要做什么？
8. 本次明确不做什么？
9. 哪些模块/文件/配置不能修改？

### 参考资料
10. 是否有设计文档？
11. 是否有参考实现？
12. 是否有历史方案？

### 交付
13. 最终交付什么？
14. 完成标准是什么？
15. 如何验证成功？

## 使用示例

### 示例 1：添加新功能

**用户输入：**
```
/dev-plan 我想给 App 加一个深色模式切换功能
```

**AI 响应（阶段 1）：**
```
好的，我来帮您规划这个功能。首先了解一下背景：

1. 您的 App 当前是什么技术栈？（如 React Native、Flutter、原生 Android/iOS 等）
2. 当前是否已有主题/样式系统？如果有，在哪个模块？
3. 您期望的深色模式是跟随系统，还是可以手动切换，还是两者都要？

---
当前阶段：第 1 阶段 — 需求采访
已收集：添加深色模式切换功能
待收集：技术栈、现有主题系统、切换方式偏好
```

### 示例 2：重构代码

**用户输入：**
```
/dev-plan 我想重构网络请求模块，把回调改成 async/await
```

**AI 响应（阶段 1）：**
```
好的，我来帮您规划这个重构任务。

1. 当前网络请求模块大概涉及哪些文件？主要在哪个目录？
2. 除了回调改 async/await，这次重构还有其他目标吗？（如错误处理统一、添加重试机制等）
3. 有哪些文件或模块是您明确不希望改动的？
```

## 全局规则

| 规则 | 说明 |
|------|------|
| 每轮最多 2~3 个问题 | 逐步推进，不一次性列出所有问题 |
| 禁止跳过阶段 | 必须按顺序完成 1→2→3→4→5→6 |
| 禁止提前编码 | 未到阶段 5 不得写任何代码 |
| 需要用户确认 | 每阶段结束需确认后才能继续 |
| 诚实报告 | 交付报告不得隐瞒失败项 |

---

## 注意事项

1. **明确范围**：阶段 1 中明确「不做什么」与「不能改什么」同样重要
2. **提供参考**：如有设计文档、参考实现，请主动提供
3. **三次确认**：阶段 2/3/4 需要您三次确认，这是避免返工的关键
4. **验收清单**：阶段 4 的验收清单是最终交付的判定标准
